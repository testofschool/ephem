# EPHEM 조사와 구현 결과

**세계 최초는 아니다. 차별화 가설은 '기존 오프라인 실행 경로에 요청 수명 제한을 쉽게 붙이고 검증까지 제공한다'이다.**

Groundhog(EuroSys 2023)는 기존 함수·라이브러리·런타임·커널을 고치지 않고
요청 사이의 상태를 복원하는 방법을 이미 제시했다. nsjail과 bubblewrap도 기존
Linux 실행 파일을 격리한다. NVIDIA OpenShell은 기존 에이전트를 다시 작성하지
않고 보안 통제를 붙이는 현재의 사례다. [원문과 15개 계열 비교](PRIOR_ART.md).

## 지금 말할 수 있는 강점

- 요청마다 새 작업자를 실행하고, 개인 임시 공간과 출력의 수명을 함께 제한한다.
- 읽기 전용 파일시스템·네트워크 금지·Landlock·seccomp·cgroup을 한 경로로 묶었다.
- 종료·출력 제한·OOM·작업자 정리 검사를 통과한 뒤에만 성공 응답을 공개한다.
- 실제 Linux 커널과 변경 없는 PHP 수신 코드로 범위를 좁혀 재현했다.
- 통과한 테스트뿐 아니라 정상 응답을 통한 비밀 유출 반례와 이전 측정도 공개한다.

이 조합의 유일성이나 경쟁사 대비 우월성, 구매 의사는 아직 입증하지 않았다.
현재 공개물이 제공하는 가치는 구현과 검증의 명확성이다.

## 이번에 보강한 것

요청별 cgroup에 실행 전 진입시키고 메모리·스왑·프로세스·CPU 한도를 읽어
확인한다. OOM이나 정리 실패가 있으면 성공 출력을 내보내지 않는다. 호스트
스왑과 파이프형 코어덤프 수집기를 검사한다. 감독자가 시작 직전에 죽었을 때
다른 부모를 정상 감독자로 오인하던 구간을 수정했다. 런타임 로그에는 응답
내용의 해시를 남기지 않는다.

수명주기 12/12, 경계 검사 7/7, seccomp 검사 5/5, 시작 거부 6/6, 감독자 조기
종료 반례와 PHP 요청 4/4가 통과했다. 정확한 조건과 원자료는
[검증 기록](../evidence/RESULTS.md)에 있다. 대외 독립 보안 감사는 미실행이다.

## 제품으로 가기 위해 필요한 것

1. 요청 파서를 비권한 프로세스로 옮기고 작은 권한 실행 브로커로 분리한다.
2. 실제 오프라인 파서나 읽기 전용 CGI 한 곳에서 설치 시간·호환성·총비용을 측정한다.
3. 감독자 메모리와 동시 부하까지 포함한 운영 한도, 종료·업그레이드·복구를 검증한다.
4. nsjail/bubblewrap 및 다른 격리 경계와 같은 조건으로 비교한다.
5. 외부 보안 검토를 받고, 필요하면 gVisor나 microVM 백엔드로 커널 경계를 바꾼다.

초기 고객 가설은 외부 입력을 처리하는 오프라인 변환기·파서·읽기 전용 CGI를
운영하는 플랫폼/애플리케이션 보안 담당자다. DB·세션·외부 API가 핵심인 앱은
현재 범위에 맞지 않는다. 유료 수요나 고객 수정 비용 0은 아직 측정하지 않았다.

“패치가 필요 없다”, “취약점이 몇 개든 안전하다”, “물리적으로 탈취 불가능하다”는
성립하지 않는다. 현재 요청의 데이터는 정상 응답으로 유출될 수 있고, 커널과
감독자도 신뢰 경계다. Zero-Persistence는 **요청 작업자의 상태를 재사용하지 않는
제한된 목표**로 설명해야 한다. 소스 수정이 없었던 예제와 무배포·무비용은 다르다.
