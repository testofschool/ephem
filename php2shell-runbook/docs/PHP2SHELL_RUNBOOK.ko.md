# PHP2Shell 긴급 대응 런북 (한국어) — 바꾸기 전에 무엇이 깨지는지부터

CVE-2026-109618 / -109619 ("PHP2Shell")은 PHP 세션 업로드 진행(session upload progress) 처리에서 인증 없이 원격 코드가 실행될 수 있는 취약점입니다. 공식 패치는 2026-10-21에 나왔습니다. 이 문서는 **패치를 당장 적용할 수 없는 서버**를 위한 것입니다.

**이 문서가 다른 안내와 다른 점:** 임시조치를 "켜라"가 아니라, **그 조치가 당신의 사이트에서 무엇을 깨뜨리는지 먼저 확인하는 법**을 담았습니다. 수치는 모두 측정했고 출처를 답니다. 서버를 대신 바꿔 주지 않습니다. 당신이 읽고, 당신이 적용합니다.

## 0. 먼저: 읽기 전용 자가 진단 (서버를 바꾸지 않음)
당신 서버에서 직접 실행하세요. 네트워크도, 쓰기도, 패치도 하지 않습니다. PHP 버전·지원 상태, 업로드 진행 기능이 켜져 있는지, 그리고 **그 기능을 끄면 영향을 받는 코드 파일**을 찾아 보여 줍니다.

```sh
sh tools/diagnose.sh /path/to/your/php/code
```

출력의 `branch_status`, `session.upload_progress.enabled`, `status`(USED / not referenced) 세 줄만 보면 아래 어느 경우인지 정해집니다.

## 1. 공식 패치가 있는 경우 (PHP 8.2 ~ 8.5)
- 최신 패치 릴리스로 올리세요: **8.5.12, 8.4.27, 8.3.36, 8.2.35** 이상 (출처: KISA 권고, 2026-10-22).
- **반드시 PHP 워커를 재시작**하세요. 안 하면 구버전이 메모리에서 계속 돕니다 — PHP-FPM, Apache mod_php, php-cgi, LiteSpeed, FrankenPHP. 컨테이너는 이미지를 재배포하세요. (출처: KISA)
- 8.2는 **2026-12-31**에 보안 지원이 끝납니다. 연말까지 8.3+로 옮길 계획을 세우세요. (출처: KISA / endoflife)

## 2. 공식 패치가 없는 경우 (PHP 8.1 이하 — EOL)
PHP.net은 8.1·8.0·7.4용 **최소 소스 패치**만 공개했고 새 빌드는 내지 않았습니다. 7.3 이하는 PHP.net에서 아무것도 받지 못합니다. (출처: ComputingForGeeks, 2026-10-22) 선택지는 셋입니다:
1. **배포판 백포트** — Ubuntu Pro, Ondřej Surý의 Debian/Ubuntu 저장소, cPanel, AlmaLinux, Remi 등이 일부 브랜치에 패치 빌드를 냈습니다. 대개 무료. 먼저 확인하세요.
2. **유료 LTS** — HeroDevs NES(5.6/7.x/8.0~8.2), TuxCare ELS(5.2~7.4), Zend. 드롭인 런타임. 가격은 견적제.
3. **지원 버전으로 이전** — 근본 해결. 2–3절의 임시조치로 시간을 번 뒤 진행.

## 3. 임시조치 — 그리고 그것이 깨뜨리는 것 (측정값)
패치나 이전을 당장 못 하면, 공격 표면인 업로드 진행 기능을 끕니다:

```ini
; php.ini 또는 PHP-FPM pool 설정에 둘 것 (ini_set()·.user.ini 로는 적용 금지)
session.upload_progress.enabled = 0
```
적용 후 **PHP 워커 재시작**. (출처: KISA, braindetox 2026-10-24)

**이 설정은 기본값이 켜짐(1)입니다** — PHP 8.3.6에서 직접 확인(이 저장소 `evidence/DETECTOR_TEST.txt`). 끄면 **세션 기반 업로드 진행률 표시 기능만** 꺼집니다. 파일 업로드 자체는 막히지 않습니다. 진행률 바(JS가 `$_SESSION[ini_get("session.upload_progress.prefix")...]`를 폴링하는 화면)를 쓰는 곳만 영향을 받습니다.

→ **그 화면을 쓰는지 모르면** 0절의 진단 스크립트가 `upload_progress`를 참조하는 파일을 찾아 줍니다. `not referenced`로 나오면 끄더라도 앱 동작이 바뀔 가능성은 낮습니다(프레임워크·플러그인 코드는 별도 확인). `USED`로 나오면 그 파일을 먼저 검토하세요.

추가 완충(KISA): WAF·웹서버·프록시에서 요청 크기 제한, 업로드가 불필요하면 업로드 요청 차단. **임시조치만으로는 완전히 막을 수 없으므로** 결국 패치·이전이 필요합니다.

## 4. 침해가 의심되면 (KISA)
- 외부 연결을 먼저 끊고, 로그·프로세스·연결 정보를 수집한 뒤 분석하세요.
- **서버를 재시작·종료하지 마세요** — 메모리의 증거가 지워집니다.
- 패치 전에 노출됐다면 DB 비밀번호·API 키·관리자 비밀번호를 교체하세요.
- 공개된 PoC 코드를 실행해 확인하려 하지 마세요(악성일 수 있음). 버전과 로그로 판단하세요.
